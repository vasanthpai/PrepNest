# v0.1 step 12: CI workflow, PR title check and first pull request

**Ticket:** [#7](https://github.com/vasanthpai/PrepNest/issues/7) · **Branch:** `feature/v0.1-foundation` ·
**Commit:** `ci: add CI workflow and PR title check` · **PR:** [#8](https://github.com/vasanthpai/PrepNest/pull/8)

## Goal

Run every quality check automatically on every pull request and push to `main`, enforce
Conventional Commits PR titles, and open the first pull request.

## What changed

| File                                                          | Change                                                                       |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `.github/workflows/ci.yml`                                    | New: `npm ci` → lint → format → generated types → type check → tests → build |
| `.github/workflows/pr-title.yml`                              | New: Conventional Commits title, lowercase subject                           |
| `package.json`                                                | Scripts `cf-typegen:check` and `check` (all CI checks except build)          |
| `docs/ci-cd.md`                                               | New: workflows, what each check catches, hardening, reading failures         |
| `README.md`                                                   | CI status badge, link to CI/CD doc                                           |
| `docs/setup.md`, `CONTRIBUTING.md`, `docs/release-process.md` | Use `npm run check`                                                          |

## Why

- **A clean Linux machine** catches what a Windows laptop hides: case-sensitive paths, missing
  files, lockfile drift.
- **SHA-pinned actions, least-privilege permissions, timeouts, concurrency**: the standard
  hardening for GitHub Actions.
- **`pull_request` instead of `pull_request_target`** for the title check: `pull_request_target`
  runs the workflow file from `main`, so it wouldn't have run on this first PR. It also has
  write-capable permissions this check doesn't need.

## Proof it works

| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
