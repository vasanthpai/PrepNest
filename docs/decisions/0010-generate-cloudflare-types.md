# 0010. Generate Cloudflare types on install, don't commit them

- **Status:** Accepted
- **Date:** 2026-10-09
- **Ticket:** [#13](https://github.com/vasanthpai/PrepNest/issues/13)

## Context

`worker-configuration.d.ts` (types for our Cloudflare variables and the Workers runtime) is generated
by `wrangler types`. In step 8 we committed it, and in step 12 CI checked it was up to date.

Dependabot's first Wrangler update (PR #12) failed that check: a newer Wrangler ships a newer
runtime, so the generated runtime types change. The check was right, but the design meant **every**
Wrangler update would fail until someone regenerated the file by hand.

## Decision

Don't commit generated files. `worker-configuration.d.ts` is git-ignored and regenerated by an npm
`postinstall` script (`wrangler types`), so `npm install` / `npm ci` always produce types that match
the installed Wrangler and the current `wrangler.jsonc`. The `cf-typegen:check` CI step is removed.

## Consequences

- Dependency updates can't make the types stale; there's nothing to keep in sync.
- Type checking still covers the real types: CI runs `npm ci` (which generates them) before `astro check`.
- `npm install` takes about a second longer.
- Generating locally includes secret **names** from `.dev.vars` (never values), so local types may
  list a few more names than CI's. Values are always validated by zod at runtime (ADR 0006).

## Alternatives considered

- **Keep committing + regenerate on each Wrangler update**: manual step on every Dependabot PR.
- **Commit only the env part (`--include-runtime=false`)** and take runtime types from
  `@cloudflare/workers-types`: two sources of truth that can disagree with the installed runtime.
- **Let Dependabot PRs fail and fix by hand**: trains everyone to ignore red CI.
